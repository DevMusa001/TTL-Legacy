# Fuzz Testing Corpus

This directory contains seed corpus files for libfuzzer to use when fuzzing the TTL Vault contract entry points.

## Directory Structure

- `fuzz_create_vault/` - Seed inputs for the create_vault entry point
- `fuzz_deposit/` - Seed inputs for the deposit entry point
- `fuzz_withdraw/` - Seed inputs for the withdraw entry point
- `fuzz_check_in/` - Seed inputs for the check_in entry point

## Corpus Generation

Seed corpus files are generated by `generate_corpus.py` and stored in the respective subdirectories. libfuzzer will:

1. Use these seed inputs as starting points
2. Generate mutations of these inputs
3. Track coverage and interesting inputs
4. Build up a corpus of inputs that trigger new code paths

## Running Fuzz Tests with Corpus

```bash
# Run specific fuzz target with corpus
cargo fuzz run fuzz_create_vault corpus/fuzz_create_vault -- -max_len=1024

# Run all fuzz targets
cargo fuzz run fuzz_deposit corpus/fuzz_deposit -- -max_len=1024
cargo fuzz run fuzz_withdraw corpus/fuzz_withdraw -- -max_len=1024
cargo fuzz run fuzz_check_in corpus/fuzz_check_in -- -max_len=1024
```

## Seed Corpus Inputs

### fuzz_create_vault

- **valid_basic**: Different owner and beneficiary, reasonable interval (1 day)
- **invalid_zero_interval**: Zero interval (should error)
- **invalid_same_owner_beneficiary**: Owner equals beneficiary (should error)
- **edge_max_interval**: Very large interval (u64::MAX)
- **valid_with_token**: Valid input with custom token address
- **boundary_min_interval**: Minimum valid interval (1 second)

### fuzz_deposit

- **valid_basic**: Simple deposit (1000 units to vault 1)
- **invalid_zero_amount**: Zero amount (should error)
- **invalid_negative_amount**: Negative amount (should error)
- **edge_balance_overflow**: Balance approaching i128::MAX
- **edge_deposit_limit_exceeded**: Deposit limit check
- **large_deposit**: Large deposit amount (1 billion units)

### fuzz_withdraw

- **valid_basic**: Simple withdrawal (100 units from 1000 balance)
- **invalid_zero_amount**: Zero amount (should error)
- **invalid_insufficient_balance**: Withdrawal exceeds balance (should error)
- **edge_withdrawal_threshold_exceeded**: Withdrawal approval threshold check
- **edge_minimum_balance_guard**: Minimum balance guard enforcement
- **boundary_exact_minimum_balance**: Exact withdrawal to minimum balance

### fuzz_check_in

- **valid_on_time**: On-time check-in (1000 sec after 100, interval 86400)
- **invalid_zero_interval**: Zero interval (should error)
- **invalid_vault_expired**: Current time >= last_check_in + interval (should error)
- **edge_ttl_cap_exceeded**: Very large interval exceeding TTL cap
- **edge_inactivity_penalty**: Testing penalty calculation with missed intervals
- **boundary_just_before_expiry**: Check-in just before expiry

## Corpus Maintenance

The fuzzer automatically expands the corpus during execution. To keep discovered failures:

1. Run the fuzzer for extended periods (10+ minutes recommended)
2. The fuzzer will create new corpus entries for:
   - Inputs that trigger coverage
   - Inputs that trigger crashes or panics
   - Inputs that violate invariants

Example crash/failure:
```
corpus/fuzz_create_vault/crash-1d4a2e3...
corpus/fuzz_create_vault/oom-2a3b1c4...
corpus/fuzz_create_vault/leak-3f2e1d...
```

These are automatically saved and should be committed to ensure regressions are caught.

## Troubleshooting

### "Corpus not found"
If you haven't generated the corpus yet, create the directories:
```bash
mkdir -p corpus/{fuzz_create_vault,fuzz_deposit,fuzz_withdraw,fuzz_check_in}
python generate_corpus.py  # If using corpus generation script
```

### Large Corpus Size
If the corpus grows too large, libfuzzer has options to trim it:
```bash
cargo fuzz cmin fuzz_create_vault  # Minimize corpus
```

### Memory/CPU Limits
Adjust fuzzer settings in CI or local runs:
```bash
cargo fuzz run fuzz_create_vault -- -max_len=1024 -timeout=10 -rss_limit_mb=2048
```
